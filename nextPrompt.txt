## Task Description

Implement the four analytics events that instrument the camera capture
decision pipeline. Every capture attempt must fire exactly one of
`photo_captured` or a rejection event, never both. Exposure warnings fire
independently of capture outcome. All four events share a common property
schema with event-specific extensions. This is a pure instrumentation task —
no UI changes, no capture logic changes, no sensor pipeline changes.

- [ ] Define the `CaptureAnalyticsEvent` sealed class hierarchy with four
      concrete subtypes, one per event
- [ ] Define the shared `CaptureEventProperties` value type carrying
      properties common to all four events
- [ ] Implement `CaptureAnalyticsService` — the single class responsible
      for building and dispatching events to the existing analytics sink
- [ ] Wire `CaptureAnalyticsService` into the capture decision call sites
      in the existing pipeline (the exact wiring points are specified below)
- [ ] Write unit tests covering event construction, property population,
      mutual exclusivity of capture/rejection events, and dispatch call
      counts

import 'package:flutter/foundation.dart';

/// Properties shared across all four capture analytics events.
@immutable
class CaptureEventProperties {

  /// Microseconds since Unix epoch.
  final int sensorTimestampUs;

  /// Device model string. Sourced from device_info_plus at service init.
  final String deviceModel;

  /// Platform: 'android' or 'ios'.
  final String platform;

  const CaptureEventProperties({
    required this.pitchLevel,
    required this.pitchRad,
    required this.stabilityScore,
    required this.stabilityConfidence,
    required this.sensorTimestampUs,
    required this.deviceModel,
    required this.platform,
  });

  Map<String, dynamic> toMap() => {
        'pitch_level':           pitchLevel.name,
        'pitch_rad':             pitchRad,
        'stability_score':       stabilityScore,
        'stability_confidence':  stabilityConfidence,
        'sensor_timestamp_us':   sensorTimestampUs,
        'device_model':          deviceModel,
        'platform':              platform,

### Step 2: Define the CaptureAnalyticsEvent sealed hierarchy

Create `lib/features/camera/analytics/capture_analytics_event.dart`:

```dart
import 'package:flutter/foundation.dart';
import 'capture_event_properties.dart';

/// Sealed base for all four capture pipeline analytics events.
/// Each subtype maps to exactly one analytics event name.
sealed class CaptureAnalyticsEvent {
  final CaptureEventProperties properties;
  const CaptureAnalyticsEvent(this.properties);

  /// The snake_case event name sent to the analytics sink.
  String get eventName;

  /// Full property map merged from shared + event-specific properties.
  Map<String, dynamic> toMap();
}

// ─── photo_captured ──────────────────────────────────────────────────────────

/// Fired when a capture attempt succeeds: frame is sharp, exposure is
/// acceptable, stability gate passes, and the JPEG is written to disk.
@immutable
class PhotoCapturedEvent extends CaptureAnalyticsEvent {
  /// FrameQualityResult.blur.score of the accepted frame. Higher = sharper.
  final double blurScore;

  /// FrameQualityResult.exposure.meanLuminance of the accepted frame.
  final double meanLuminance;

  /// Absolute file path of the written JPEG.
  final String framePath;

  const PhotoCapturedEvent({
    required super.properties,
    required this.blurScore,
    required this.meanLuminance,
    required this.framePath,
  });

  @override
  String get eventName => 'photo_captured';

  @override
  Map<String, dynamic> toMap() => {
        ...properties.toMap(),
        'blur_score':      blurScore,
        'mean_luminance':  meanLuminance,
        'frame_path':      framePath,
      };
}

// ─── photo_rejected_blur ─────────────────────────────────────────────────────

/// Fired when a capture attempt is rejected because the frame is blurry.
/// Mutually exclusive with photo_captured for the same attempt.
@immutable
class PhotoRejectedBlurEvent extends CaptureAnalyticsEvent {
  /// FrameQualityResult.blur.score that triggered rejection.
  final double blurScore;

  /// Native blur threshold at time of rejection (from native constants).
  /// Pass this in from the call site — do not hardcode here.
  final double blurThreshold;

  const PhotoRejectedBlurEvent({
    required super.properties,
    required this.blurScore,
    required this.blurThreshold,
  });

  @override
  String get eventName => 'photo_rejected_blur';

  @override
  Map<String, dynamic> toMap() => {
        ...properties.toMap(),
        'blur_score':      blurScore,
        'blur_threshold':  blurThreshold,
      };
}

// ─── photo_rejected_motion ───────────────────────────────────────────────────

/// Fired when a capture attempt is rejected because the stability score
/// is below the rejection threshold at shutter-fire time.
/// Mutually exclusive with photo_captured for the same attempt.
@immutable
class PhotoRejectedMotionEvent extends CaptureAnalyticsEvent {
  /// StabilityScore.score that triggered rejection. Always < rejection threshold.
  final double stabilityScoreAtRejection;

  /// The threshold the score failed to meet.
  final double rejectionThreshold;

  /// gyroMag of the most recent SensorFrame — quantifies how much motion.
  final double gyroMag;

  const PhotoRejectedMotionEvent({
    required super.properties,
    required this.stabilityScoreAtRejection,
    required this.rejectionThreshold,
    required this.gyroMag,
  });

  @override
  String get eventName => 'photo_rejected_motion';

  @override
  Map<String, dynamic> toMap() => {
        ...properties.toMap(),
        'stability_score_at_rejection': stabilityScoreAtRejection,
        'rejection_threshold':          rejectionThreshold,
        'gyro_mag':                     gyroMag,
      };
}

// ─── photo_warned_exposure ───────────────────────────────────────────────────

/// Fired when the exposure is outside acceptable range at the moment
/// the user attempts a capture. This event fires INDEPENDENTLY of
/// capture outcome — it may co-occur with photo_captured (capture
/// succeeded despite marginal exposure) or with a rejection event
/// (if blur or motion also triggered). Never suppressed.
@immutable
class PhotoWarnedExposureEvent extends CaptureAnalyticsEvent {
  /// true if ExposureResult.isUnderexposed was true.
  final bool isUnderexposed;

  /// true if ExposureResult.isOverexposed was true.
  final bool isOverexposed;

  /// ExposureResult.meanLuminance at the time of the warning.
  final double meanLuminance;

  const PhotoWarnedExposureEvent({
    required super.properties,
    required this.isUnderexposed,
    required this.isOverexposed,
    required this.meanLuminance,
  });

  @override
  String get eventName => 'photo_warned_exposure';

  @override
  Map<String, dynamic> toMap() => {
        ...properties.toMap(),
        'is_underexposed': isUnderexposed,
        'is_overexposed':  isOverexposed,
        'mean_luminance':  meanLuminance,
      };
}
```

### Step 4: Implement CaptureAnalyticsService

Create `lib/features/camera/analytics/capture_analytics_service.dart`:

```dart
import 'package:flutter/foundation.dart';
import 'analytics_sink.dart';
import 'capture_analytics_event.dart';
import 'capture_event_properties.dart';

/// Builds and dispatches capture pipeline analytics events.
///
/// Inject [AnalyticsSink] at construction time.
/// Call [dispatch] once per capture decision — never call it twice
/// for the same attempt.
class CaptureAnalyticsService {
  final AnalyticsSink _sink;

  const CaptureAnalyticsService(this._sink);

  /// Dispatches [event] to the analytics sink.
  /// Logs a debug warning if called with a null-equivalent event in
  /// debug mode but never throws — analytics must never crash the pipeline.
  Future<void> dispatch(CaptureAnalyticsEvent event) async {
    try {
      await _sink.track(event.eventName, event.toMap());
    } catch (e, stack) {
      // Analytics dispatch failure must NEVER propagate to the capture
      // pipeline. Log only — do not rethrow.
      debugPrint('[CaptureAnalytics] dispatch failed: $e\n$stack');
    }
  }
}
```

## Analytics Events

**Event: `photo_captured`**
Trigger: Capture attempt succeeds — frame is sharp, exposure acceptable,
         stability gate passes, JPEG written to disk
Properties (all shared + event-specific):
  - pitch_level: string (PitchLevel.name)
  - pitch_rad: double
  - stability_score: double
  - stability_confidence: double
  - sensor_timestamp_us: int
  - device_model: string
  - platform: 'android' | 'ios'
  - blur_score: double
  - mean_luminance: double
  - frame_path: string

**Event: `photo_rejected_blur`**
Trigger: Capture attempt rejected — FrameQualityResult.blur.isBlurry == true
Properties (all shared + event-specific):
  - [all 7 shared]
  - blur_score: double
  - blur_threshold: double

**Event: `photo_rejected_motion`**
Trigger: Capture attempt rejected — stabilityScore.score < kStabilityRejectionThreshold
Properties (all shared + event-specific):
  - [all 7 shared]
  - stability_score_at_rejection: double
  - rejection_threshold: double
  - gyro_mag: double

**Event: `photo_warned_exposure`**
Trigger: ExposureResult.isUnderexposed || isOverexposed at capture attempt time.
         Fires before and independently of capture/rejection decision.
Properties (all shared + event-specific):
  - [all 7 shared]
  - is_underexposed: bool
  - is_overexposed: bool
  - mean_luminance: double

**Mutual exclusivity rule:**
For a single capture attempt, exactly one of `photo_captured`,
`photo_rejected_blur`, or `photo_rejected_motion` must fire.
`photo_warned_exposure` may fire in addition to any of the above.
No other combination is valid.

## Edge Cases to Handle

- [ ] `CaptureAnalyticsService.dispatch()` sink throws → caught internally,
      logged via `debugPrint`, never rethrown; unit test #21 covers this;
      a broken analytics connection must never prevent a capture from
      completing
- [ ] Both `isUnderexposed` and `isOverexposed` are true simultaneously
      (hardware fault) → `PhotoWarnedExposureEvent` still fires with both
      set to true; the `ExposureResult` assert in debug mode will have
      already flagged this upstream; analytics must not add a second guard
- [ ] `kNativeBlurThreshold` is not yet a named Dart constant when this
      task runs → pass `0.0` as the threshold in the wiring; add a
      `// TODO: replace with real threshold constant` comment; file
      BUG-QA-ANALYTICS-THRESHOLD in the report section of the commit
      message
- [ ] `_buildProperties` called before `_deviceModel` is populated
      (controller init race) → default `_deviceModel` to `'unknown'`
      if not yet populated; never block capture on device info fetch
- [ ] `activePitchLevel` is null at wiring point (no level selected yet)
      → default to `PitchLevel.eye` if null; document this default with
      a `// DEFAULT:` comment at the call site
- [ ] Dispatch called more than once for the same capture attempt due to
      a double-trigger bug upstream → `CaptureAnalyticsService` does not
      deduplicate; the call site is responsible; if observed in testing,
      file a bug against `CaptureController`, not the analytics service

## Constraints

- `CaptureAnalyticsService.dispatch()` must be `async` and must
  `await _sink.track()` — fire-and-forget is not acceptable; the caller
  awaits dispatch so that test assertions on `fake.calls` are synchronous
- `CaptureAnalyticsEvent` must be a `sealed` class — this enforces
  exhaustive pattern matching in any future switch on event type and
  prevents undocumented subtypes being added without updating this file
- All four `toMap()` implementations must spread `properties.toMap()`
  first and then add event-specific keys — event-specific keys must
  never shadow shared keys; if a key collision is introduced in future,
  the event-specific key wins silently; add a `// NOTE:` comment to
  this effect in the base `toMap()` pattern
- `CaptureEventProperties` must be `const`-constructible — confirmed by
  using `const kTestProperties` in the test file
- The `AnalyticsSink` interface file must be the only place the sink
  contract is defined — do not duplicate the `track()` signature
  elsewhere
