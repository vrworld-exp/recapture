```dart
class PitchBand {
  final String id;          // e.g. "low", "mid", "high"
  final double minDegrees;  // inclusive
  final double maxDegrees;  // exclusive
  final int segments;       // how many capture positions around this band
  const PitchBand({required this.id, required this.minDegrees, required this.maxDegrees, required this.segments});

  factory PitchBand.fromMap(Map<String, dynamic> m) => PitchBand(
    id: m['id'] as String? ?? 'band',
    minDegrees: (m['minDegrees'] as num?)?.toDouble() ?? 0,
    maxDegrees: (m['maxDegrees'] as num?)?.toDouble() ?? 90,
    segments: (m['segments'] as num?)?.toInt() ?? 12,
  );
  Map<String, dynamic> toMap() => {'id': id, 'minDegrees': minDegrees, 'maxDegrees': maxDegrees, 'segments': segments};
}

class CaptureThresholds {
  final double minSharpness;     // 0..1 reject blurry frames below this
  final double minCoveragePct;   // % of segments that must be captured to allow finishing
  final double maxTiltDeltaDeg;  // max device tilt deviation tolerated
  const CaptureThresholds({required this.minSharpness, required this.minCoveragePct, required this.maxTiltDeltaDeg});

  factory CaptureThresholds.fromMap(Map<String, dynamic> m) => CaptureThresholds(
    minSharpness: (m['minSharpness'] as num?)?.toDouble() ?? 0.45,
    minCoveragePct: (m['minCoveragePct'] as num?)?.toDouble() ?? 80,
    maxTiltDeltaDeg: (m['maxTiltDeltaDeg'] as num?)?.toDouble() ?? 12,
  );
  Map<String, dynamic> toMap() => {'minSharpness': minSharpness, 'minCoveragePct': minCoveragePct, 'maxTiltDeltaDeg': maxTiltDeltaDeg};
}

class CaptureConfig {
  final int version;
  final List<PitchBand> pitchBands;
  final CaptureThresholds thresholds;
  const CaptureConfig({required this.version, required this.pitchBands, required this.thresholds});

  static const CaptureConfig bundledDefault = CaptureConfig(
    version: 0,
    pitchBands: [
      PitchBand(id: 'low',  minDegrees: 0,  maxDegrees: 30, segments: 12),
      PitchBand(id: 'mid',  minDegrees: 30, maxDegrees: 60, segments: 10),
      PitchBand(id: 'high', minDegrees: 60, maxDegrees: 90, segments: 8),
    ],
    thresholds: CaptureThresholds(minSharpness: 0.45, minCoveragePct: 80, maxTiltDeltaDeg: 12),
  );

  int get totalSegments => pitchBands.fold(0, (sum, b) => sum + b.segments);

  factory CaptureConfig.fromMap(Map<String, dynamic> m) {
    final bands = (m['pitchBands'] as List?)
        ?.whereType<Map>()
        .map((e) => PitchBand.fromMap(e.cast<String, dynamic>()))
        .toList();
    return CaptureConfig(
      version: (m['version'] as num?)?.toInt() ?? 0,
      pitchBands: (bands == null || bands.isEmpty) ? bundledDefault.pitchBands : bands,
      thresholds: m['thresholds'] is Map
          ? CaptureThresholds.fromMap((m['thresholds'] as Map).cast<String, dynamic>())
          : bundledDefault.thresholds,
    );
  }
  Map<String, dynamic> toMap() => {
    'version': version,
    'pitchBands': pitchBands.map((b) => b.toMap()).toList(),
    'thresholds': thresholds.toMap(),
  };
}
```

### Step 4: Config notifier / provider
In `lib/features/config/application/config_notifier.dart`:

```dart
class ConfigNotifier extends Notifier<CaptureConfig> {
  @override
  CaptureConfig build() {
    _bootstrap();                 // async, non-blocking
    return CaptureConfig.bundledDefault; // immediate, always-valid value
  }

  Future<void> _bootstrap() async {
    final repo = ref.read(configRepositoryProvider);
    // 1) load cache for a better-than-default starting point
    final cached = await repo.readCached();
    if (cached != null) state = sanitizeCaptureConfig(cached);
    // 2) refresh from remote in background
    try {
      final remote = sanitizeCaptureConfig(await repo.fetchRemote());
      state = remote;
      await repo.writeCache(remote);
    } catch (_) {
      // stay on cache/default; silent (log/analytics only)
    }
  }

  Future<void> refresh() => _bootstrap();
}

final captureConfigProvider = NotifierProvider<ConfigNotifier, CaptureConfig>(ConfigNotifier.new);
```

`build()` returns a synchronous, always-valid value so consumers never see loading/null — they get bundled defaults instantly, upgraded to cached, then remote.

- **Analytics:** a single typed event layer shared by both, with a canonical tracking plan.
- **QA:** hermetic tests for the auth happy path, local persistence, token-refresh behavior, and offline behavior.

## 2. Shared Conventions (inherited by ALL tasks)

Every per-task prompt assumes these; do not re-decide them per task.

**Auth & identity**
- Access token = JWT with `sub` = userId, short TTL (default 900s), signed with the configured key.
- Refresh token = opaque, stored hashed, rotating with reuse detection (pending decision #4); plaintext returned once.
- A shared JWT auth middleware resolves the user from the access token and attaches the userId; protected routes sit behind it. **(Still needs its own prompt — see §4.)**
- Ownership is ALWAYS derived from the token, NEVER accepted from request body/query/header.

**API contract**
- Validation via Zod on every input.
- Error responses are enumeration-safe and generic: not-found and not-owned both return identical `404` (never `403`, which leaks existence).
- Consistent error envelope: `{ status: "error", code, message }`; success: `{ status: "success", ... }`.
- Tunables (TTLs, limits, cooldowns) come from config/env — never hardcoded literals.

**Data**
- Soft delete via `deletedAt` (or the existing schema flag); soft-deleted rows are excluded from reads.
- The `Project` DTO shape is IDENTICAL across `GET /projects`, `GET /projects/:id`, `POST /projects`, `PATCH /projects/:id`. One shape, defined once.
- `updatedAt` is set on create (= `createdAt`) and bumped on real mutations (rename), so list ordering by `updatedAt desc` is meaningful.

**PII & secrets hygiene**
- Never log or emit raw phone, email, OTP/code, JWT, refresh token, or password.
- Identifiers in analytics/logs are hashed via one shared util (so `identifier_hash`/`user_id_hash` join across events).

**Analytics**
- One `AnalyticsEvent` name const; no string literals scattered. One Zod property schema per event. `snake_case` properties.
- Emission is fire-and-forget: it MUST NOT block, delay, or break the request path; failures are swallowed + logged.

**Testing**
- Hermetic: no real network/providers/connectivity; isolated DB/Hive temp dirs; deterministic (no wall-clock sleeps).
- Order-independent, repeatable, with full teardown. NEVER modify production code to make a test pass — surface bugs instead.

**Client**
- Token expiry recovers via refresh transparently; logout happens ONLY on refresh failure.
- Hive is the local store for the project cache AND the offline create outbox; both durable across restart.

## 4. Inline Specs for the Two Missing Backend Pieces

These block other work; generate full prompts for them, but here is enough to unblock sequencing.

### JWT Auth Middleware (shared dependency for ALL protected routes)
- Reads the `Authorization: Bearer <accessToken>` header (or cookie, per decision #3).
- Verifies the JWT signature + expiry against the configured key; on failure returns the standard `401` envelope.
- On success, attaches the resolved userId (from `sub`) to the request for downstream handlers.
- Does NOT hit the DB on every request unless the design requires user re-validation (decide); pure token verification is the default.
- Must be the single chokepoint — handlers never re-implement token parsing.
- Every protected endpoint in §3 (`GET/POST/PATCH/DELETE /projects`, `GET /projects/:id`) sits behind it. `send-otp`, `verify-otp`, `refresh` do NOT (they establish the session). `/remote-config` depends on decision #6.

### `GET /projects/:id` (single project fetch)
- Behind the JWT middleware; owner-scoped exactly like `GET /projects`.
- Validates `:id`; returns the `Project` DTO (same shape as the rest) on a successful, owned, non-deleted fetch.
- Not-found / not-owned / soft-deleted all return identical `404`.
- Is the likely emit point for the `project_resumed` analytics event (with debounce — see that analytics prompt).

## 6. What NOT To Do (phase-wide)

- Do NOT let any task re-decide a §2 shared convention locally (e.g. a different error envelope, a second analytics const, request-supplied ownership).
- Do NOT build protected endpoints before the JWT middleware exists — they would each hand-roll token parsing.
- Do NOT emit or log raw PII/secrets anywhere, in any track.
- Do NOT let analytics or persistence failures break a request/auth path.
- Do NOT modify production code to make any QA test pass.
- Do NOT proceed past M0 with §0 decisions unresolved — especially the project enums and ownership model, which silently shape multiple tasks.
- Do NOT introduce new frameworks/SDKs where the repo already has one (HTTP client, rate limiter, analytics SDK, mocking lib).
