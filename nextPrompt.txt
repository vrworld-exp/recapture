# NEW FEATURE: Canonical S3 Key Naming — prod/{userId}/{projectId}/{jobId}/images/{LEVEL}/{filename}.jpg
# Product: maya-viewer (Capture Summary + Upload Pipeline)
# Scope: New Feature (Backend API — shared utility / contract)
# Priority: High

---

## Task Description

Define a single canonical S3 key-naming scheme for capture images and implement it as one reusable
utility that every part of the upload pipeline uses to build and parse keys. The format is:

  {env}/{userId}/{projectId}/{jobId}/images/{LEVEL}/{filename}.jpg

where `{env}` is the environment prefix (`prod` in production), `{LEVEL}` is the capture level
(A / B / C), and `{filename}` is the per-image file name. Because `POST /jobs` advertises the key
prefix in the upload plan, the upload engine writes objects to these keys, and `finalize` lists
objects under the prefix to verify counts, all three MUST derive keys from this single utility so
they never disagree.

- [ ] Implement a key-builder that produces keys in exactly the specified format
- [ ] Implement a matching parser that extracts {env, userId, projectId, jobId, level, filename} from a key
- [ ] Drive the environment prefix from configuration (prod / staging / dev), not a hardcoded literal
- [ ] Sanitize/validate every path segment to prevent key injection and path traversal
- [ ] Replace any existing inline/ad-hoc key construction in `POST /jobs` and the prefix used by
      `finalize` with calls to this utility

## Files to Inspect First

1. The `POST /jobs` handler — find where `keyPrefix` / the upload plan keys are currently constructed.
   This must switch to the new key-builder, and the prefix it advertises must be the builder's
   job-level prefix.
2. The `finalize` handler — find where it lists objects under the job's key prefix; it must use the
   same builder's prefix so listing and writing align exactly.
3. The job model — confirm `userId` (owner reference), `projectId`, and `jobId` are all available on
   the job record, since all three are key segments. If `userId` is not currently stored on the job,
   that is a gap (see Assumptions).
4. The capture level definition (A / B / C) — confirm the exact level identifiers and casing used
   elsewhere so `{LEVEL}` matches (the format shows uppercase).
5. The environment/config source — find how the service reads its environment (prod/staging/dev) so
   `{env}` is config-driven.
6. Any existing path/string utility location — place this key utility alongside existing shared utils
   following the project's conventions; do NOT scatter it inside a single handler.

## Implementation Instructions

### Step 1: Define the key utility (single source of truth)
Create one module exposing:
- `buildImageKey({ userId, projectId, jobId, level, filename })` → full key string
- `buildJobImagePrefix({ userId, projectId, jobId })` → `{env}/{userId}/{projectId}/{jobId}/images/`
  (and optionally a per-level prefix `.../images/{LEVEL}/`)
- `parseImageKey(key)` → `{ env, userId, projectId, jobId, level, filename }` or a clear failure
The builder reads `{env}` from config. All callers use these functions — no inline string templates.

### Step 2: Sanitize and validate segments
Each interpolated segment (`userId`, `projectId`, `jobId`, `level`, `filename`) must be validated/
sanitized before composing the key:
- Reject or strip path separators (`/`, `\`), `..`, leading dots, whitespace, and control characters.
- Constrain `level` to the allowed set (A/B/C) — reject anything else.
- Constrain `filename` to a safe charset and ensure the final key ends in `.jpg` (lowercase) exactly
  once; do not allow a caller-supplied extension to double it up or override it.
- Reject empty segments. Invalid input throws a clear error rather than producing a malformed key.

### Step 3: Normalize the LEVEL segment
Map the codebase's capture level value to the `{LEVEL}` segment using a single normalization (e.g.,
uppercase A/B/C). Builder and parser must use the same mapping so a built key round-trips through the
parser back to the original level.

### Step 4: Wire callers to the utility
Update `POST /jobs` to advertise `buildJobImagePrefix(...)` as the plan's key prefix, and update
`finalize` to list under the same prefix via the same function. Confirm the upload engine's expected
key layout matches what the builder produces (it consumes the plan's prefix/keys — see Assumptions).

### Step 5: Round-trip guarantee
Ensure `parseImageKey(buildImageKey(x))` returns `x` for all valid inputs. The parser must also reject
keys that don't match the scheme rather than returning partial/garbage segments.

## API / Data Contract

Key format (exact):
  {env}/{userId}/{projectId}/{jobId}/images/{LEVEL}/{filename}.jpg

Examples (env = prod, level uppercase):
  prod/u_123/proj_456/job_789/images/A/frame_0001.jpg
  prod/u_123/proj_456/job_789/images/C/frame_0090.jpg

Job-level prefix (used for listing/verification):
  prod/u_123/proj_456/job_789/images/

Segment rules:
  env       — from config: "prod" | "staging" | "dev" (confirm exact values)
  userId    — non-empty, sanitized, no separators
  projectId — non-empty, sanitized, no separators
  jobId     — non-empty, sanitized, no separators
  LEVEL     — exactly one of A | B | C (uppercase)
  filename  — safe charset; key always ends in a single lowercase ".jpg"

## What NOT to Change

- Do NOT hardcode `prod` — the environment prefix is config-driven so staging/dev don't write into prod paths.
- Do NOT leave any inline/duplicate key construction in `POST /jobs`, `finalize`, or elsewhere — all key
  building/parsing goes through the one utility.
- Do NOT change the upload engine's transfer logic; only ensure the keys it's given match this scheme.
- Do NOT alter the job model beyond what's needed to access `userId`/`projectId`/`jobId` for key building
  (if `userId` must be added to the job record, flag it — see Assumptions).
- Do NOT change bucket configuration or the S3 client.

## Edge Cases to Handle

- [ ] `filename` already containing `.jpg` → key ends in exactly one `.jpg`, not `.jpg.jpg`.
- [ ] `filename` containing path separators, `..`, spaces, or unicode/control chars → sanitized or
      rejected; never produces a traversal or a key with embedded slashes that change the hierarchy.
- [ ] Any segment empty/null → throws a clear validation error; no key with `//` or missing segments.
- [ ] `level` outside A/B/C → rejected.
- [ ] Wrong environment → keys reflect the configured env (a staging deploy never emits `prod/...`).
- [ ] `parseImageKey` on a non-conforming key (wrong depth, missing `images/`, wrong extension) →
      explicit failure, not silent partial parse.
- [ ] Case sensitivity → `{LEVEL}` is uppercase consistently; `.jpg` is lowercase consistently; the
      parser does not accept mixed-case variants unless explicitly normalized.
- [ ] Round-trip → every key the builder emits parses back to the exact inputs.

## Constraints

- Exactly one utility builds and parses these keys; duplicated key logic anywhere is a failure condition.
- The environment prefix MUST come from configuration; `prod` must never be hardcoded.
- All segments MUST be sanitized to prevent key injection / path traversal before composition.
- The builder's prefix used by `POST /jobs` and the prefix listed by `finalize` MUST be the same function
  output — writing and verification cannot diverge.
- The key always terminates in a single lowercase `.jpg`.

## Acceptance Criteria

- [ ] `buildImageKey` produces keys exactly matching `{env}/{userId}/{projectId}/{jobId}/images/{LEVEL}/{filename}.jpg`
- [ ] `buildJobImagePrefix` produces the job-level `.../images/` prefix used by `finalize`
- [ ] The environment prefix is config-driven (verified: staging config yields `staging/...`, not `prod/...`)
- [ ] `parseImageKey(buildImageKey(x))` round-trips to `x` for all valid inputs
- [ ] `parseImageKey` rejects non-conforming keys with a clear failure
- [ ] Segments with separators / `..` / whitespace / control chars are sanitized or rejected (no traversal)
- [ ] `level` is constrained to A/B/C; invalid levels rejected
- [ ] A filename already ending in `.jpg` does not produce `.jpg.jpg`
- [ ] `POST /jobs` and `finalize` both build/list keys via the shared utility (no inline templates remain)
- [ ] The keys produced match the layout the upload engine writes to (verified against its contract)
- [ ] No TypeScript errors (`tsc --noEmit` passes); lint clean; unit tests green
- [ ] Code reviewed against "What NOT to Change" — engine, bucket config, and job transfer logic untouched

## Testing Instructions

1. Unit-test `buildImageKey` for each level (A/B/C) and assert exact string output against expected keys.

```typescript
export async function updateProjectStatus(
```

```dart
class LevelPhotoDeficit {
  final String levelId;
  final int count;
  final int required;

  LevelPhotoDeficit({
    required this.levelId,
    required this.count,
    required this.required,
  });

List<LevelPhotoDeficit> get photoDeficits {
  final minRequired = config.minPhotosPerLevel;
  final photoCountByLevel = <String, int>{};

  for (final item in captureItems) {
    if (item.fileType == FileType.photo) {
      photoCountByLevel[item.levelId] =
          (photoCountByLevel[item.levelId] ?? 0) + 1;
    }

  return levelsPresent
      .map((levelId) {
        final count = photoCountByLevel[levelId] ?? 0;
        return LevelPhotoDeficit(
          levelId: levelId,
          count: count,
          required: minRequired,
        );
      })
      .where((deficit) => deficit.count < deficit.required)
```

```typescript
const S3_KEY_PATTERN =
  /^projects\/([a-zA-Z0-9_-]+)\/jobs\/([a-zA-Z0-9_-]+)\/([a-zA-Z0-9_-]+)\/([a-zA-Z0-9_-]+)\.([a-zA-Z0-9]+)$/;

const ALLOWED_EXTENSIONS = ["jpg", "jpeg", "png", "heic", "mp4", "mov", "json"];

/**
 * Canonical S3 key convention for all capture pipeline files:
 *   projects/{projectId}/jobs/{jobId}/{levelId}/{fileId}.{ext}
 *
 * This is the ONLY function in the codebase permitted to construct an S3 key
 * for job/capture files. Do not concatenate key strings inline elsewhere —
 * route every call site through this function.
 */
export function buildS3Key(params: {
  projectId: string;
  jobId: string;
  levelId: string;
  fileId: string;
  ext: string;
}): string {
  const { projectId, jobId, levelId, fileId, ext } = params;
  const normalizedExt = ext.toLowerCase().replace(/^\./, "");

  if (!ALLOWED_EXTENSIONS.includes(normalizedExt)) {
    throw new Error(`Unsupported file extension for S3 key: "${ext}"`);
  }
  for (const [name, value] of Object.entries({ projectId, jobId, levelId, fileId })) {
    if (!value || !/^[a-zA-Z0-9_-]+$/.test(value)) {
      throw new Error(`Invalid ${name} for S3 key construction: "${value}"`);
    }
  }

  const key = `projects/${projectId}/jobs/${jobId}/${levelId}/${fileId}.${normalizedExt}`;

  if (!isValidS3Key(key)) {
    // Defensive — should be unreachable given the checks above
    throw new Error(`Constructed S3 key failed validation: "${key}"`);
  }
  return key;
}

export function isValidS3Key(key: string): boolean {
  return S3_KEY_PATTERN.test(key);
}
```

```swift
class BackgroundUploadManager: NSObject {
  static let shared = BackgroundUploadManager()
  static let sessionIdentifier = "com.mayasabhaxr.upload.background"

  private var backgroundSession: URLSession!
  var backgroundCompletionHandler: (() -> Void)?
  private var eventSink: FlutterEventSink?

  private override init() {
    super.init()
    let config = URLSessionConfiguration.background(withIdentifier: Self.sessionIdentifier)
    config.isDiscretionary = false
    config.sessionSendsLaunchEvents = true
    backgroundSession = URLSession(configuration: config, delegate: self, delegateQueue: nil)
  }

  func setEventSink(_ sink: FlutterEventSink?) { self.eventSink = sink }

  func enqueueUpload(taskID: String, localFileURL: URL, uploadURL: URL, headers: [String: String]) {
    guard FileManager.default.fileExists(atPath: localFileURL.path) else {
      sendToFlutter(event: ["type": "failure", "taskID": taskID,
                             "errorCode": -1, "errorDescription": "Local file not found",
                             "retryRecommended": false])
      return
    }
    var request = URLRequest(url: uploadURL)
    request.httpMethod = "PUT"
    headers.forEach { request.setValue($1, forHTTPHeaderField: $0) }
    let task = backgroundSession.uploadTask(withRequest: request, fromFile: localFileURL)
    task.taskDescription = taskID
    task.resume()
    persistTaskMetadata(taskID: taskID, localFileURL: localFileURL, uploadURL: uploadURL, headers: headers)
  }

  private func persistTaskMetadata(taskID: String, localFileURL: URL, uploadURL: URL, headers: [String: String]) {
    var all = UserDefaults.standard.dictionary(forKey: "bg_upload_tasks") ?? [:]
    all[taskID] = ["localPath": localFileURL.path, "uploadURL": uploadURL.absoluteString,
                    "headers": headers, "enqueuedAt": ISO8601DateFormatter().string(from: Date())]
    UserDefaults.standard.set(all, forKey: "bg_upload_tasks")
  }

  private func clearTaskMetadata(taskID: String) {
    var all = UserDefaults.standard.dictionary(forKey: "bg_upload_tasks") ?? [:]
    all.removeValue(forKey: taskID)
    UserDefaults.standard.set(all, forKey: "bg_upload_tasks")
  }

  private func sendToFlutter(event: [String: Any]) {
    DispatchQueue.main.async { self.eventSink?(event) }
  }
}

extension BackgroundUploadManager: URLSessionTaskDelegate {
  func urlSession(_ session: URLSession, task: URLSessionTask, didCompleteWithError error: Error?) {
    let taskID = task.taskDescription ?? "unknown"
    let statusCode = (task.response as? HTTPURLResponse)?.statusCode ?? -1
    if let error = error {
      sendToFlutter(event: ["type": "failure", "taskID": taskID,
                             "errorCode": (error as NSError).code,
                             "errorDescription": error.localizedDescription,
                             "retryRecommended": isRetryable(error: error)])
    } else {
      clearTaskMetadata(taskID: taskID)
      sendToFlutter(event: ["type": "success", "taskID": taskID, "statusCode": statusCode,
                             "completedAt": ISO8601DateFormatter().string(from: Date())])
    }
  }

  func urlSession(_ session: URLSession, task: URLSessionTask, didSendBodyData bytesSent: Int64,
                   totalBytesSent: Int64, totalBytesExpectedToSend: Int64) {
    let taskID = task.taskDescription ?? "unknown"
    let progress = totalBytesExpectedToSend > 0
      ? Double(totalBytesSent) / Double(totalBytesExpectedToSend) : -1.0
    sendToFlutter(event: ["type": "progress", "taskID": taskID, "bytesSent": totalBytesSent,
                           "totalBytes": totalBytesExpectedToSend, "progress": progress])
  }

  func urlSessionDidFinishEvents(forBackgroundURLSession session: URLSession) {
    DispatchQueue.main.async {
      self.backgroundCompletionHandler?()
      self.backgroundCompletionHandler = nil
    }
  }

  private func isRetryable(error: Error) -> Bool {
    let code = (error as NSError).code
    return [NSURLErrorTimedOut, NSURLErrorNetworkConnectionLost, NSURLErrorNotConnectedToInternet].contains(code)
  }
}
```

```dart
class LevelPhotoDeficit {
  final String levelId;
  final int count;
  final int required;
  LevelPhotoDeficit({required this.levelId, required this.count, required this.required});
  int get missing => required - count;
}

List<LevelPhotoDeficit> get photoDeficits {
  final minRequired = config.minPhotosPerLevel;
  final photoCountByLevel = <String, int>{};
  for (final item in captureItems) {
    if (item.fileType == FileType.photo) {
      photoCountByLevel[item.levelId] = (photoCountByLevel[item.levelId] ?? 0) + 1;
    }
  }
  final levelsPresent = captureItems.map((item) => item.levelId).toSet();
  return levelsPresent
      .map((levelId) => LevelPhotoDeficit(
            levelId: levelId,
            count: photoCountByLevel[levelId] ?? 0,
            required: minRequired,
          ))
      .where((d) => d.count < d.required)
      .toList();
}

bool get hasPhotoDeficit => photoDeficits.isNotEmpty;
```

```typescript
export function validateCaptureManifest(manifest: CaptureManifest): ManifestValidationResult {
  const errors: ManifestValidationError[] = [];

  if (manifest.files.length !== manifest.declaredFileCount) {
    errors.push({
      rule: "FILE_COUNT_MISMATCH",
      message: `Manifest declared ${manifest.declaredFileCount} files but contains ${manifest.files.length}`,
      detail: { declared: manifest.declaredFileCount, actual: manifest.files.length },
    });
  }

  const presentLevelIds = new Set(manifest.files.map((f) => f.levelId));
  const missingLevels = manifest.requiredLevels.filter((id) => !presentLevelIds.has(id));
  if (missingLevels.length > 0) {
    errors.push({
      rule: "MISSING_REQUIRED_LEVELS",
      message: `Required levels missing from manifest: ${missingLevels.join(", ")}`,
      detail: { missingLevels },
    });
  }

  const photosByLevel = new Map<string, number>();
  for (const file of manifest.files) {
    if (file.fileType === "photo") {
      photosByLevel.set(file.levelId, (photosByLevel.get(file.levelId) ?? 0) + 1);
    }
  }
  const underMinLevels: Array<{ levelId: string; count: number; required: number }> = [];
  for (const levelId of presentLevelIds) {
    const count = photosByLevel.get(levelId) ?? 0;
    if (count < manifest.minPhotosPerLevel) {
      underMinLevels.push({ levelId, count, required: manifest.minPhotosPerLevel });
    }
  }
  if (underMinLevels.length > 0) {
    errors.push({
      rule: "INSUFFICIENT_PHOTOS_PER_LEVEL",
      message: `${underMinLevels.length} level(s) have fewer than ${manifest.minPhotosPerLevel} photo(s)`,
      detail: { levels: underMinLevels },
    });
  }
```

#### Step 2.1: Add `buildS3Key` / `isValidS3Key` to `s3Service.ts`

```typescript
const S3_KEY_PATTERN = /^projects\/([a-zA-Z0-9_-]+)\/jobs\/([a-zA-Z0-9_-]+)\/([a-zA-Z0-9_-]+)\/([a-zA-Z0-9_-]+)\.([a-zA-Z0-9]+)$/;
const ALLOWED_EXTENSIONS = ["jpg", "jpeg", "png", "heic", "mp4", "mov", "json"];

export function buildS3Key(params: { projectId: string; jobId: string; levelId: string; fileId: string; ext: string }): string {
  const { projectId, jobId, levelId, fileId, ext } = params;
  const normalizedExt = ext.toLowerCase().replace(/^\./, "");
  if (!ALLOWED_EXTENSIONS.includes(normalizedExt)) {
    throw new Error(`Unsupported file extension for S3 key: "${ext}"`);
  }
  for (const [name, value] of Object.entries({ projectId, jobId, levelId, fileId })) {
    if (!value || !/^[a-zA-Z0-9_-]+$/.test(value)) {
      throw new Error(`Invalid ${name} for S3 key construction: "${value}"`);
    }
  }
  const key = `projects/${projectId}/jobs/${jobId}/${levelId}/${fileId}.${normalizedExt}`;
  if (!isValidS3Key(key)) throw new Error(`Constructed S3 key failed validation: "${key}"`);
  return key;
}

export function isValidS3Key(key: string): boolean {
  return S3_KEY_PATTERN.test(key);
}
```

This function is now the ONLY place permitted to construct an S3 key. Audit

#### Step 2.2: Add Multipart Upload Helpers to `s3Service.ts`

```typescript
const PART_SIZE_BYTES = 5 * 1024 * 1024;
const PRESIGN_EXPIRES_SECONDS = 3600;

export async function initiateMultipartUpload(s3Key: string, mimeType: string): Promise<string> {
  const result = await s3Client.send(new CreateMultipartUploadCommand({
    Bucket: process.env.S3_BUCKET_NAME, Key: s3Key, ContentType: mimeType,
  }));
  if (!result.UploadId) throw new Error(`No UploadId returned for key: ${s3Key}`);
  return result.UploadId;
}

export async function generatePartPresignedUrls(
  s3Key: string, uploadId: string, sizeBytes: number
): Promise<Array<{ partNumber: number; url: string }>> {
  const totalParts = Math.ceil(sizeBytes / PART_SIZE_BYTES);
  return Promise.all(
    Array.from({ length: totalParts }, (_, i) => i + 1).map(async (partNumber) => {
      const command = new UploadPartCommand({
        Bucket: process.env.S3_BUCKET_NAME, Key: s3Key, UploadId: uploadId, PartNumber: partNumber,
      });
      const url = await getSignedUrl(s3Client, command, { expiresIn: PRESIGN_EXPIRES_SECONDS });
      return { partNumber, url };
    })
  );
}
```

#### Step 2.3: Add `getUploadUrlsForJob` to `jobService.ts` + Route

```typescript
export async function getUploadUrlsForJob(jobId: string): Promise<UploadUrlsResponse> {
  const job = await JobModel.findById(jobId);
  if (!job) throw new NotFoundError(`Job ${jobId} not found`);

  const fileResults: UploadUrlsResponse["files"] = [];
  for (const file of job.files) {
    if (file.uploadStatus === "completed") {
      fileResults.push({ fileId: file.fileId, skipped: true, parts: [] });
      continue;
    }
    const uploadId = await initiateMultipartUpload(file.s3Key, file.mimeType);
    const parts = await generatePartPresignedUrls(file.s3Key, uploadId, file.sizeBytes);
    file.s3UploadId = uploadId;
    file.uploadStatus = "in_progress";
    fileResults.push({ fileId: file.fileId, uploadId, parts, skipped: false });
  }
  await job.save();
  return { jobId, files: fileResults };
}
```
